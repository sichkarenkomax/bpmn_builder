# ADR-003. Формат хранения: BPMN XML как источник истины

- **Статус:** принято (деталь расширения стилей уточняется в спринте 1.3)
- **Дата:** 12.11.2026
- **Задача:** 0.6

## Контекст

Диаграмму можно хранить как внутренний JSON, как BPMN XML или как оба. Пользователи
приносят файлы из Bizagi, Camunda Modeler, bpmn-js и ждут, что после сохранения у нас
схема откроется там же без потерь. Экспорт в BPMN XML — обязательное требование этапа 1.

## Решение

1. **Источник истины — BPMN 2.0 XML** (`bpmn:definitions` + `bpmndi:BPMNDiagram`).
   Храним целиком, включая координаты, размеры, waypoints и `isExpanded`.
2. **Незнакомые расширения сохраняем.** Парсер не отбрасывает чужие namespace-
   элементы и атрибуты (в том числе `camunda:*`, `bizagi:*`), иначе импорт ломает файлы.
3. **JSON-проекция** (элементы, связи, свойства) — производная, для индексации,
   поиска и API. Из неё нельзя «собрать обратно» XML: только из XML.
4. **Версия = снапшот полного XML** + метаданные (автор, время, комментарий).
   Диффы считаются на лету, не хранятся.
5. **Стили и легенда.** Сначала — нативные атрибуты BPMNDI (`bi:Shape` → `dc:Bounds`,
   цвет в `di:extension`/CSS-классе невозможно, поэтому цвет заливки храним в
   собственном расширении). Собственное расширение:
   `xmlns:bs="https://bpmn-studio.dev/schema/1.0"`, элементы `bs:style`, `bs:legend`,
   `bs:meta`. Всё, что можно выразить стандартом, в расширение не тащим.

Схема таблиц:

```sql
diagram(id, title, status, owner_id, created_at, updated_at, current_version_id, etag)
diagram_version(id, diagram_id, xml, author_id, created_at, message)
diagram_acl(diagram_id, user_id, role)          -- этап 4
comment(id, diagram_id, element_id, body, author_id, resolved_at)
attachment(id, diagram_id, element_id, s3_key, filename, content_type, size)
```

## Альтернативы

- **Только JSON + генератор XML** — теряются чужие расширения и точные координаты,
  round-trip перестаёт быть честным.
- **Только XML без проекции** — каждый поиск/фильтр требует парсинга, нельзя индексировать.

## Последствия

- Обязательны property-тесты round-trip и golden-файлы из Bizagi/Camunda (задача 1.1.8).
- Валидация входящего XML по `Semantic.xsd`/`BPMNDI.xsd` на входе API (задача 1.1.7).
- При смене формата стилей миграция версий нужна с первого релиза — поэтому решение
  по `bs:style` фиксируем до спринта 1.3.

## Дополнение от 12.11.2026 (по итогам спринта 1.1)

1. **Плоскости DI.** Если в диаграмме есть пулы, все фигуры (участники, дорожки, узлы,
   потоки) лежат в **одной** плоскости коллаборации. bpmn-js и большинство инструментов
   рисуют одну плоскость за раз; при отдельных плоскостях на процесс виден только первый
   пул. У процессов без пулов остаётся своя плоскость.
2. **Сохранение без изменений — байт в байт.** Пока правок нет, `serialize_bpmn`
   возвращает исходный XML: чужие `camunda:*`/`bizagi:*` не теряются. При правках
   модель собирается заново, и чужие расширения теряются — это закрывает задача 1.2.11
   (reconcile поверх исходного дерева).
3. **Канон модели.** `normalize()` описывает, что генератор дописывает по умолчанию
   (id плоскостей, точки связей, порядок артефактов, `categoryValueRef` у групп).
   Любое изменение канона — это изменение ADR, а не «мелкая правка».
