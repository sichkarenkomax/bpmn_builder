# ADR-002. Ядро редактора: bpmn-js

- **Статус:** принято
- **Дата:** 12.11.2026
- **Задача:** 0.5

## Контекст

Нужен холст уровня Bizagi: палитра, drag&drop, пулы и дорожки, ручки ресайза,
ортогональная маршрутизация, undo/redo, inline-редактирование подписей, сериализация
в BPMN 2.0 XML с сохранением координат (BPMNDI). Писать это с нуля — 3–4 месяца и
хуже качество на старте.

## Решение

Берём **bpmn-js 18** (MIT, Camunda/bpmn.io) как ядро и расширяем своими модулями:

- `additionalModules` — стили элементов (заливка/обводка/шрифт), легенда, бейджи;
- `bpmn-js-token-simulation` (MIT) — как основа оверлея прогона на этапе 3,
  с последующей заменой логики на серверный интерпретатор;
- комментарии-аннотации — собственный модуль поверх `diagram-js` (этап 4).

Правило: **всё, что не про отрисовку, живёт на сервере.** Клиент не валидирует схему
окончательно и не исполняет процесс.

## Альтернативы

| Вариант | Плюсы | Минусы |
|---|---|---|
| Свой SVG-рендерер | полный контроль, нет зависимости | +3–4 месяца, undo/маршрутизация/ресайз с нуля |
| Konva/canvas | проще анимации | canvas-текст и доступность хуже, BPMN DI руками |
| bpmn-js + форк | контроль над спорными местами | конфликты при обновлениях, поддержка форка |

## Последствия

- Экономия ~3 месяцев на старте, валидный BPMN XML «из коробки».
- Ограничения: часть UX (например, нестандартные ручки) придётся реализовывать
  через override-модули; обновления bpmn-js нужно проверять регрессионными тестами.
- Стили хранятся в расширении BPMN (см. ADR-003), а не в состоянии bpmn-js — иначе
  при перезагрузке они исчезнут.

## Риск и проверка

Риск: bpmn-js не даст нужной свободы в оформлении. Проверка — прототип кастомного
модуля стилей в спринте 1.3; если упираемся, запасной путь — собственный SVG-слой
только для режима просмотра/экспорта.
