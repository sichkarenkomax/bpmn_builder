# BPMN Studio v0.2 — валидация схемы

**Дата выпуска:** 25.11.2026 · **Версия:** 0.2.0 · **Статус:** выпущено, тег `v0.2`.
Сценарий приёмки этапа 2 пройден на живом стеке 25.11.2026.

## Что нового

- **Правила шлюзов и событий.** Exclusive/inclusive-ветка без условия, отсутствие
  и некорректный `default`, default с условием, шлюз, который одновременно
  разделяет и сливает потоки, некорректная цель событийного шлюза, граничное
  событие без существующего владельца, старт без исходящего потока, финиш
  с исходящим. Коды `BPMN-GATEWAY-001…006`, `BPMN-EVENT-001…004`.
- **Конфиг правил.** JSON-файл (`VALIDATION_RULES_FILE`) включает/выключает
  встроенные правила и меняет severity. Неизвестный код — предупреждение
  в `config_errors`, а не падение.
- **Пользовательские правила без кода:** `max_elements`, `max_outgoing_flows`,
  `required_attribute`, `forbidden_node_type`, `required_node_type`.
- **API для CI:** `POST /api/v1/diagrams/{id}/validate` возвращает `ValidationReport`,
  не создаёт версию и не меняет диаграмму. `?include=xsd,structure,gateway,event,lane`.
  `GET /validation` оставлен для UI и помечен `deprecated`.
- **Сводка при сохранении:** `PUT /bpmn` сохраняет черновик даже с ошибками и
  возвращает `X-Validation-Errors` / `X-Validation-Warnings`.
- **DOCX-отчёт:** `GET /api/v1/diagrams/{id}/validation/report.docx` и кнопка
  «DOCX» в панели проблем: шапка диаграммы, сводка, таблица находок.
- **Модель:** `default` шлюза хранится в `Node.default_flow` и переживает
  сохранение; добавлен тип `eventBasedGateway`.

## Контракт

```http
POST /api/v1/diagrams/{id}/validate?include=structure,gateway
```

```json
{
  "valid": false,
  "summary": {"errors": 1, "warnings": 1, "infos": 0},
  "findings": [
    {
      "rule_id": "BPMN-GATEWAY-001",
      "severity": "error",
      "message": "ветка «Развилка» без условия",
      "element_id": "Flow_B",
      "element_name": null,
      "line": null,
      "column": null,
      "hint": "добавьте conditionExpression или назначьте поток по умолчанию"
    }
  ],
  "duration_ms": 3.2,
  "schema_version": "1.0",
  "config_errors": []
}
```

- Схема с ошибками — это **200** и `valid=false`. Четырёхсотые ответы означают
  проблему запроса (404, 413, 429), битый сохранённый XML приходит как
  `BPMN-XSD-001` в том же отчёте.
- Лимиты: сохранённый XML до 5 МиБ, общий body-limit, timeout-middleware,
  rate limiting (по умолчанию 120 записывающих запросов в минуту на IP/токен).
- Условия не исполняются: проверяется только наличие `conditionExpression`.

## CI

```bash
BPMN_API_URL=http://localhost:8000/api/v1 BPMN_DIAGRAM_ID=<id> \
  python3 scripts/validate.py
make validate DIAGRAM_ID=<id>
```

Код возврата: `0` — `valid=true`, `1` — `valid=false`, `2` — HTTP/сетевая ошибка.
Обёртка `make validate` при ошибке возвращает `2` (стандартный код make), это
тоже ненулевой результат для CI. Токен читается из `BPMN_API_TOKEN`, в БД ничего
не пишется.

## Конфиг правил

```json
{
  "rules": {
    "BPMN-STRUCT-009": {"enabled": false},
    "BPMN-STRUCT-008": {"severity": "info"}
  },
  "disabled_rules": ["BPMN-STRUCT-007"],
  "custom_rules": [
    {"id": "BPMN-CUSTOM-001", "kind": "max_elements", "max": 50},
    {"id": "BPMN-CUSTOM-002", "kind": "required_attribute",
     "attribute": "documentation", "node_types": ["userTask"]}
  ]
}
```

Путь задаётся в `VALIDATION_RULES_FILE`; произвольный код и выражения в конфиге
не поддерживаются.

## Совместимость и ограничения

- Версия API/приложения — `0.2.0`; `schema_version` отчёта — `1.0` (поле
  `config_errors` добавлено обратносовместимо).
- `GET /validation` deprecated, но работает; фронтенд использует `POST /validate`.
- Проверяются только поддерживаемые моделью типы; вложенность подпроцессов
  и бизнес-семантика предметной области в `v0.2` не проверяются.
- Пользовательские правила — пять декларативных видов; плагинов и выражений нет.
- Rate limiting по-прежнему в памяти процесса: для нескольких воркеров нужен Redis
  (этап 6/4).
