# BPMN Studio v0.3 — исполняемая симуляция

**Версия:** 0.3.0 · **Статус:** приёмка на живом стеке пройдена 26.11.2026;
тег `v0.3` ставится после merge ветки в `main`. Дата выпуска фиксируется
вместе с тегом.

## Что нового

- **Прогон токена.** `POST /api/v1/diagrams/{id}/simulate` проводит токен по
  сохранённой версии XML: стартовые/конечные события, задачи, эксклюзивные,
  параллельные, инклюзивные и событийные шлюзы. Параллельное слияние ждёт все
  ветки, инклюзивное — только запущенные; `max_steps` останавливает цикл.
- **Условия без `eval`.** `conditionExpression` и присваивания скрипт-задач
  вычисляются безопасным парсером (`app/simulation/expressions.py`): числа,
  строки, `true`/`false`, арифметика, сравнения, `&&`/`||`/`!`. Ошибка выражения
  даёт 400 с понятным текстом, а не 500.
- **Переменные на каждом шаге.** Шаг отчёта несёт снимок переменных после себя и
  список `changed`; скрипт-задача исполняет строки `имя = выражение`.
- **Подпроцессы.** Свёрнутый подпроцесс проходит одним шагом, раскрытый
  (`isExpanded`) — через внутренние стартовые события и внутренние концы на
  исходящие потоки подпроцесса. Вложенность любая, переменные общие, счётчики и
  токен видны внутри.
- **Граничный таймер.** Прерывающее граничное событие с таймером останавливает
  подпроцесс и уводит токен по своему потоку; `wait_ms` считается для
  `timeDuration`. `cancelActivity="false"` запускает параллельную ветку, не
  останавливая подпроцесс.
- **Граничные ошибки.** Ошибка скрипта внутри подпроцесса перехватывается
  ближайшим `errorEventDefinition` (включая внешний подпроцесс) и уводит токен
  по потоку события; без перехвата прогон по-прежнему даёт `SimulationError`.
  Корневые `bpmn:error` и `errorRef` разбираются и переживают round-trip.
- **Ручной выбор ветки.** Если условие не задано или переменных не хватает,
  отчёт приходит с `decision`; клиент передаёт `choices` (id шлюза → id потока) и
  продолжает прогон с текущего шага.
- **Панель «Симуляция».** Запуск/перезапуск, шаг вперёд/назад, автопроигрывание
  0.5–2×, журнал, подсветка пути, «Переменные на шаге» с подсветкой изменённых,
  токен на геометрии холста при зуме и панораме, тепловая карта.
- **Сохранённые прогоны.** `simulation_run` хранит версию XML, переменные,
  `choices`, отчёт и время; история ограничена 20 последними прогонами на
  диаграмму. API: `POST/GET/DELETE /diagrams/{id}/simulation-runs`.
- **Тест-кейсы.** `test_case` хранит имя, входные переменные, `choices`,
  ожидаемые шаги и переменные, а также `version_id` — версию XML, к которой
  привязан кейс. `POST /test-cases/{id}/run` прогоняет именно эту версию и
  возвращает `passed`, `step_diffs` и `variable_diffs`; `PATCH` меняет имя и
  ожидания, `version_id: null` перепривязывает к текущей версии.
- **Миграция `0003`** создаёт `simulation_run` и `test_case` (каскадное удаление
  вместе с диаграммой).

## Контракт

```http
POST /api/v1/diagrams/{id}/simulate
Content-Type: application/json

{"variables": {"amount": 1200, "approved": true}, "choices": {}, "max_steps": 500}
```

```json
{
  "schema_version": "1.0",
  "completed": true,
  "steps": [
    {
      "index": 1,
      "token": 1,
      "node_id": "StartEvent_1",
      "node_name": "Заявка получена",
      "node_type": "startEvent",
      "action": "completed",
      "flow_id": null,
      "message": null,
      "wait_ms": null,
      "variables": {"amount": 1200, "approved": true},
      "changed": []
    }
  ],
  "counts": {"StartEvent_1": 1, "Task_Review": 1, "EndEvent_1": 1},
  "tokens_started": 1,
  "tokens_completed": 1,
  "max_steps": 500,
  "decision": null
}
```

- Прогон **не пишет в диаграмму** и не создаёт версию XML.
- 400 — XML не разбирается или схема невыполнима (нет старта, тупик, ошибка
  условия, неверный `choices`); 404 — нет диаграммы; 409 — нет сохранённой
  версии; 413 — XML больше 5 МиБ; 429 — rate limit.
- `decision.branches` содержит потоки шлюза; повторный запрос с выбранным
  `choices` продолжает тот же прогон.
- Тест-кейс сравнивает шаги по `node_id` и только те переменные, которые
  перечислены в `expected_variables`; `passed` требует `completed` и отсутствия
  расхождений.

## Ограничения

- Не моделируются компенсация, событийные подпроцессы, multi-instance и
  граничные события сообщений/сигналов. Граничное событие-ошибка перехватывает
  только сбой скрипт-задачи.
- Нет JS/Groovy-рантайма: скрипт-задача понимает только `имя = выражение`
  безопасного парсера.
- Сообщения, пулы и дорожки в прогоне не участвуют; симуляция идёт по одному
  процессу.
- Тест-кейсы, созданные до миграции `0004`, не имеют `version_id` и
  запускаются по текущей версии диаграммы до перепривязки.
